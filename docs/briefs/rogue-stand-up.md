# Brief: the Rogue's stand-up

The first message of a run ([AGENTS.md](../../AGENTS.md#the-rules)), as written; a run starts on it once the owner approves it.

1. Request: "stand-up for all". This run: the Rogue (`workshop-rogue`), the table's `stand-up` row.
2. Question: which one technique of her route loses the most (fails or is slowest), and does changing it bring her row down?
3. Find it: `npm run evaluate -- rise --protocol placed-bodies`, then `npm run evaluate -- rise --protocol moving-bodies`; read the `workshop-rogue` lines against the Warrior's.
4. Change: that one technique as the Rogue runs it: her own record where the technique keeps one a body (`assets/skills/recovery/`). No other body, no Mind, no drill, no table code; a change that needs code other bodies share stops the run with a report.
5. Not to retry (`docs/approaches.md`, Standing up): shorter stage times; more strength; a route that presses her chest up on her arms.
6. After the change: `node research/skills/recovery/edge-profiles.mjs --model workshop-rogue --write`, then commit the change and the rebuilt profiles before the row is read: a reading is kept only where the commit holds its code unchanged.
7. Measure: `npm run evaluate -- table --body workshop-rogue --skill stand-up`, before (15.16, 23.61, 24.53, 13.94, 18.08 s) and after with `--fresh`.
8. Machine time: 60 minutes of play in all.
9. The Rise drill's `-bodies` protocols and the one-body profile rebuild are played here for the first time: a defect in either is fixed at its cause and named in the report.
10. Stops at the row read after one change, kept if better and reverted if not; gates passing, committed, not pushed. One report: the row and the technique's Rise lines before and after, and what is unchecked.
