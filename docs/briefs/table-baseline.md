# Brief: the table's baselines on the drills as they are

The first message of a run ([AGENTS.md](../../AGENTS.md#the-rules)), as written; approved by the owner, and run as written.

1. Request: the owner's goal, "get skills into a good state, and then use them to have interesting fights in the Arena"; asked to play the table for baselines, "yes, write the baseline brief". Why: every one of the table's 116 cells reads "not read" ([the roadmap](../roadmap.md#now)), so no skill can be judged or raised until its cell is played on the drills as they are.
2. Question: what does each cell read on its drills at the code as committed? It is answered when every reading is whole and named as its cell's baseline ([the table](../reference/the-table.md)).
3. Start on a clean working copy at `HEAD` on main: evaluate keeps a result only where the commit holds its code (`--write`, `scripts/evaluate.mjs`). Nothing else heavy runs on the machine meanwhile; port 5180 is left alone.
4. Play: `npm run evaluate -- table --play --baseline --workers 30`, waited for to its exit, its console output kept in `.tmp/table-baseline/play.txt`; the same command again while a pass plays anything (a reading cut by evaluate's ten-minute budget goes on from its kept trials). 47 readings, 11,779 trials: the way-up drill 5,340 (4,800 falls and 540 bouts), Travel 1,760, Locomotion 1,835, the Strike drill 2,772, Cover 72 (counted from the cases, playing nothing).
5. Machine time: about 25 minutes of 30 workers were every trial to run to its cap (one body about 0.9 ms a step, two about 2.3 ms), so 20 to 60 minutes with setup; the budget is 2 hours, at which the run stops with what is whole kept.
6. Changed: the saved results and baselines (`assets/evaluations/way-up.json`, `locomotion.json`, `travel.json`, `strike.json`, `cover.json`), committed on main in one commit, not pushed, with this brief's deletion and the roadmap's line on "not read" brought to what the table reads. No skill, Mind, drill or evaluation is changed.
7. A defect that faults a trial or stops a reading is fixed at its cause in a commit of its own under the checks for code (`npm run check`, `npm test`, `npm run build`) and named in the report. Where `node scripts/fingerprint.mjs --compare` against the commit before shows a pose moved, every reading already whole is played again (`--fresh` on its cells) before the baselines stand; otherwise the play goes on. A reading left not whole names no baseline and is reported with its faults.
8. Measure: `npm run evaluate -- table`, which plays nothing, its grid kept in `.tmp/table-baseline/table.txt`; and for each skill's row, `npm run evaluate -- table --skill <skill>` for its outcome counts.
9. Not read by this run: 480 Hz (the table reads 120), any reel, any profile or fight.
10. Stops when 2 is answered or at the budget; no next item, no skill touched. One report: the grid; for each skill the cells' values, best and worst, and what the trials came to (landed, refused, outside, fell; stood, failed, not exercised, obstructed; orders' seconds lost and falls); the readings not whole and why; each defect fixed; the time taken; what is unchecked.
