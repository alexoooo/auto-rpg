# Brief: the table's baselines on the drills as they are

The first message of a run ([AGENTS.md](../../AGENTS.md#the-rules)), as written; approved by the owner, and run as written.

1. Request: the owner's goal, "get skills into a good state, and then use them to have interesting fights in the Arena"; asked to play the table for baselines, "yes, write the baseline brief". Why: every one of the table's 116 cells reads "not read" ([the roadmap](../roadmap.md#now)), so no skill can be judged or raised until its cell is played on the drills as they are. The whole table is played at once, as asked, not a row.
2. Question: what does each cell read on its drills at the code as committed? It is answered when every reading is whole and named as its cell's baseline ([the table](../reference/the-table.md)); a whole reading with nothing counted is an answer, marked so.
3. Start on a clean working copy at `HEAD` on main, `CORE_ENGINE` unset: evaluate keeps a result only where the commit holds its code (`--write`, `scripts/evaluate.mjs`). Nothing else heavy runs on the machine meanwhile; port 5180 is left alone. Before: `npm run evaluate -- table`, kept in `.tmp/table-baseline/table-before.txt`.
4. Play: `npm run evaluate -- table --play --baseline --workers 30`, waited for to its exit, its output appended to `.tmp/table-baseline/play.txt`; the same command again while a pass plays trials (its readings' `N played`, not a `playing` line; a reading cut by evaluate's ten-minute budget goes on from its kept trials). Whether a reading is whole is read from the table, never from an exit code; a pass that plays no trial while a reading is not whole is a defect (7). 47 readings, 11,779 trials: the way-up drill 5,340 (4,800 falls and 540 bouts), Travel 1,760, Locomotion 1,835, the Strike drill 2,772, Cover 72 (counted from the cases, playing nothing).
5. Machine time: about 25 minutes of 30 workers were every trial to run to its cap (one body about 0.9 ms a step, two about 2.3 ms), so 20 to 60 minutes with setup. Budget, for playing: no pass starts 2 hours after the first; a pass still running at 3 hours is stopped with its whole process tree (`taskkill /T /F /PID <its pid>`), its trials left in `.tmp/evaluations/` for a later play; then the checks, the commit and the report.
6. Changed: the saved results and baselines (`assets/evaluations/way-up.json`, new, `locomotion.json`, `travel.json`, `strike.json`, `cover.json`), committed on main in one commit after any defect's, whole or not, not pushed, with this brief's deletion and the roadmap's "not read" paragraph brought to what the table reads. No skill, Mind, drill or evaluation is changed but by a defect's fix (7).
7. A defect (a trial faulted, a world refused for a case, a reading stopped by an error or left not whole by a pass that played none of its trials; not a low value, a skill's refusal of a blow or a fall) is fixed at its cause: first `node scripts/fingerprint.mjs --json .tmp/table-baseline/fingerprint-before.json` on the commit before, then the fix in a commit of its own under the checks for code (`npm run check`, `npm test`, `npm run build`), named in the report, and `node scripts/fingerprint.mjs --compare .tmp/table-baseline/fingerprint-before.json`. No pose moved and no case new or gone: the play goes on. Otherwise, or where either fingerprint fails, the baselines already named are of the code before, so nothing more is played and the run reports. A reading left not whole names no baseline and is reported with its faults.
8. Measure: `npm run evaluate -- table`, which plays nothing, kept in `.tmp/table-baseline/table.txt`; for each skill's row, `npm run evaluate -- table --skill <skill>`, and where its lines do not count the trials' outcomes, `--by <field>` on a condition's field (a way up's `level` for its shoved falls and `gap` for its bouts; a strike's `hand` or `gap`); all read saved results only.
9. Not read by this run: 480 Hz (the table reads 120), any reel, any profile, any fight beyond the way-up drill's bouts and the fingerprint of 7.
10. Stops when 2 is answered, at 7 or at the budget; no next item, no skill touched. One report: the grid before and after; for each skill the cells' values, best and worst, and what the trials came to (landed, refused, outside, fell; stood, failed attempts, not exercised, obstructed; orders' seconds lost and falls; cover's life lost and covers attacked); the readings not whole and why; each defect fixed; the time taken; what is unchecked. `.tmp/table-baseline/` is deleted once the report is written.
