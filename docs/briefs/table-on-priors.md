The first message of a run ([AGENTS.md](../../AGENTS.md#the-rules)), as written; approved by the agent the owner set to drive the stand-up goal, and run as written.

1. Request: "we only want to evaluate a skill on its own merit"; "definitely we don't want profiles to have an impact on skills training"; of a cell's mind reading no profile, "Please actually do it this time." `91cf6e0c` made it so: every cell now reads `option-prior`, Option Mind on its hand-set priors alone ([the table](../reference/the-table.md)), and all 71 cells read "not read". This run reads them, and nothing else: no code, record or profile changes.
2. Question: what does each cell read on `option-prior`, and how far is it from what the same cell read on `option`, the mind that priced by profiles? The cells with no reading on `option` (13) are read for the first time.
3. Play, with `CORE_ENGINE` unset: `npm run evaluate -- table --play --baseline --workers 22`, a pass playing each reading with no whole result (every case an unfaulted trial), keeping it (`assets/evaluations/<drill>.json`) and naming it its cell's baseline. Passes are repeated, the same command, until one starts no reading (no `playing` line). A reading cut by evaluate's 10-minute budget goes on in the next pass and is no failure. A reading named failed at a pass's end, or left with a `fault` line of the evaluator, is a defect (9): a faulted trial is kept in the evaluator's rows and is not played again until its code changes. Once a pass starts no reading, each cell still not read is read with `npm run evaluate -- table --body <model> --skill <name>` and reported with why; the run is then unfinished for those cells, never done. No time limit. Each pass is started in the background, its console output kept in `.tmp/table-prior/`, and waited for to its exit.
4. The values before: `research/runs/table-prior/before-option.txt` (the grid read on `option` from the same saved results, playing nothing) and `before-option-stand-up.txt` (each body's stand-up lines). The two minds' readings are different subjects, so the table pairs nothing across them; their values are set side by side, unpaired.
5. The reading after: `npm run evaluate -- table`, and for each body `npm run evaluate -- table --body <model> --skill stand-up`, saved beside the before files as `after-option-prior.txt` and `after-option-prior-stand-up.txt` (that folder's `README.md` names them already).
6. Changed: the saved results and their baselines in `assets/evaluations/`, the new `option-prior` readings added beside the `option` ones, which stay. Committed on main, under the checks [AGENTS.md](../../AGENTS.md#checks-and-landing) names for assets, in one commit once a pass plays nothing; where the passes run long, a commit may also follow any pass that keeps whole readings, each holding only what was played. A reading is kept only where the commit holds its code unchanged.
7. Measure: the grid in 5 against the grid in 4, cell by cell.
8. Machine time: none set; the passes end themselves.
9. A defect met in a drill, the table or the new preset is fixed at its cause in a commit of its own, under the checks for code, and named in the report. A fix to what a case plays changes its key, and its readings are played again (`npm run evaluate -- table --body <model> --skill <name> [--loadout <left,right>] --fresh --workers 22` where they are whole, else the next pass), the evaluator's `cases to play` showing them played, not found; a reading is the drill's whole protocol, every cell it holds read again with it. A fix to how saved trials are read plays nothing: the table reads them again ([AGENTS.md](../../AGENTS.md#the-rules), rule 8), and the before files are read again as they were made (the table read with `TABLE_MIND` set to `option` in the working copy, then put back). This is the one change to code the run may make, and it improves no skill.
10. Stops once a pass plays nothing and 5 is read; no search, no next item. Nothing in `research/runs/` is committed. This brief is deleted in the run's last commit. One report: the two grids side by side, each cell's value before and after with the difference (at the grid's two decimals; the stand-up rows at their lines' three); the stand-up rows' lines; every cell not read after and why; each defect fixed; the passes, their count and hours; what is unchecked.
