# Brief: what the punch's steer keeps as one layer, apart from the legs

The first message of a run ([AGENTS.md](../../AGENTS.md#the-rules)), as written.

1. Request: the owner: "the problem that I am trying to address is development velocity, especially around iterating on and adding new skills"; "i want to implement any framework/methodology changes, and then use the warrior punch as a testbed to validate the implementation"; and, offered readings taken in one run before anything is built (a control, three fits, the edits of the installed network and the time of a `--bar`): "go ahead, update the plans and write the brief". Why: a strike's steer is trained by PPO, one to two and a half days a run, and the punch's network reads the legs and asks the stance ([the notes](../plans/2026-11-14-many-skills.md#where-the-time-goes)). The drive's settings with no network land 20 of the Warrior's 240 held-out sparring starts, against 105 steered. Whether a steer small enough to search, asking nothing of the legs, keeps those landings is unread.
2. Question: which of the installed steer's landings on the Warrior's held-out sparring starts does the straight punch keep at each cut toward a steer of one layer that reads the arm and the target and asks nothing of the legs? Each file of 4 is one cut: the installed network with one tie to the legs taken away, the network on the fit's inputs alone, and the one layer fitted to it.
3. Start on a clean working copy at `HEAD` on main, `.tmp/punch-readings/` made. Nothing else heavy runs; port 5180 is left alone. Every network file and every output the run keeps is under `.tmp/punch-readings/` and is never committed.
4. Changed, none of it asked for by the owner beyond the words in 1: `research/skills/strikes/straight-punch/punch-sparring.mjs`, and its row of `research/README.md`. **(a)** `--network <form> --out <file>` writes a network file in the installed layout (`assets/skills/strikes/straight-punch/drive.layout.json`: 59 inputs, 12 outputs) from the Warrior's installed network (`dataOf("straight-punch/drive").man.network`), keeping its `normalization` and `actionLimit`. An input is found by its name in the layout and an output by its `term`, `along` and `channel` there, never by a number written in the tool. As it writes a file the mode prints which rows and columns it set. The forms: `installed`, the network unedited (the control); `no-stance-asks`, the last layer's `heading` and two `centre` rows at zero weights and bias; `walk-on` and `walk-off`, the last layer's `walk` row at zero weights, its bias 1 and -1; `blind-legs`, the first layer's columns at zero for every `angle` and `speed` input of a `hip.`, `knee.` or `ankle.` channel and for `near foot bearing`, `far foot bearing`, `stance shifting` and `stance swinging`; `fit-inputs`, the first layer's columns at zero for every input but the fit's 16; and the three fits. The fit's 16 inputs: `target from shoulder`, `fist from target`, `fist velocity` and `centre velocity`, each across, up and ahead, and the `angle` of `shoulder.right flexion`, `shoulder.right abduction`, `shoulder.right internal rotation` and `elbow.right flexion`. **A fit** is one layer (`recoveryNetwork`, `src/core/math/learning/recovery-network.ts`). Its command plays the twin's training half (the `sparring-twin` starts `--on train` plays), steered by the installed network through `steeredTrial`, and keeps a copy of each decision's 59 inputs (`learner.inputs` is one array, written again at each decision). It solves by least squares, on the inputs as `normalization` transforms and clips them, for the installed network's eight `pushes` outputs before tanh, as `actionLimit` clamps them; `recoveryNetwork` returns them after tanh, so the tool computes them itself. Every other column is zero; its `heading` and `centre` rows are zero; its `walk` row is zero weights and bias -1. `fit` reads the 16; `fit-aged` reads them and `drive age`; `fit-spans` is a layer for each of two or three spans of `drive age`, the split the run's choice, each fitted on its span's decisions, in a file whose layer the tool chooses by `drive age` at each decision (`candidateIn`, `policyOf`). A fit's command prints the share of each output's variance it holds on those decisions. The solve's conditioning is the run's choice. **(b)** `--bar` prints, beside what it prints now: how many starts only the candidate lands and how many only the drive lands, the exact two-sided sign test's p on those two counts (1 where both are 0), and the wall-clock seconds each side took to play. Not changed: anything under `src/` or `assets/`; any record, network, layout, protocol or the bar (`RATE`, `LOW`). Nothing is installed, searched or trained.
5. Order: the tool's change, then `npm run check` and `npm test`; no test is added, since the tool runs its command line where it is imported. Then every file is written, which runs every mode once: `node research/skills/strikes/straight-punch/punch-sparring.mjs --network <form> --out .tmp/punch-readings/<form>.json` for each of `installed`, `no-stance-asks`, `walk-on`, `walk-off`, `blind-legs`, `fit-inputs`, `fit`, `fit-aged` and `fit-spans`. `installed.json` must equal the record's network, and each edit differ from it only in the rows and columns its form names. Then the tool and its README row are committed. Then the control: `installed`'s `--bar` as in 6. The control holds where its sign test's p is 0.05 or more and its damage ratio's interval, as computed and not as printed to two places, holds 1. Where it does not, the tool does not steer a network file as the game steers its record's network. A cause in research code is fixed there, in a commit of its own under `npm run check` and `npm test`, within the budget, and the control read again. A cause under `src/` is not fixed: the run reads no other file and reports the control and the cause. With a control that holds, the other eight files are read, in any order.
6. Measure: each file's starts landed of the Warrior's 240 held-out `sparring` starts beside the drive's on the same starts, with how many only one of them lands and the sign test's p: `node research/skills/strikes/straight-punch/punch-sparring.mjs --bar .tmp/punch-readings/<form>.json --workers 30 > .tmp/punch-readings/<form>.txt`, once for each of the nine forms. The drive's side of each is the measure before, the file's the measure after. Beside it, as `--bar` prints them: damage dealt a second against the drive's with its interval, life taken, falls and the table's value a trial. A `--bar` ends in PASS or FAIL against the bar of a better punch; that line is not this run's measure, and FAIL is expected.
7. Machine time: each fit's play of the training half, 127 starts three times, and nine `--bar`s of 240 starts by two sides. A sparring trial plays at most 11 s at about 0.55 s of a core a simulated second, so a side is at most 24 core-minutes and the run about 8 core-hours, under half an hour on 30 workers, by arithmetic; it is priced again from the control's printed seconds. Budget: two hours of wall-clock time from the first fit's play, a defect's fix and its replays among it. A `--bar` under way at the end finishes, nothing new starts, and the landing of 8 and the report follow.
8. Committed on main, not pushed. First the tool (5). Last, one prose commit: [the notes](../plans/2026-11-14-many-skills.md#the-readings-that-come-first), their "Where it stands" under "The readings that come first" brought to the readings, each with the command that reads it again, and "What a try's comparison costs" to the seconds of a `--bar`; the same seconds in [the played rows' notes](../plans/2026-11-14-saved-results.md#open), "What it saves a try"; a line of [the roadmap](../roadmap.md#parked-plans) only where a reading makes it untrue; and this brief deleted. Where the drive's side lands other than 105 of the 240, those notes take the run's figure wherever they give that one. It is prose: `node --test tests/documents.test.mjs`, `git diff --check`, the line-ending gate. Its message holds every file's figures as a table, the spans chosen and each fit's share of each output's variance.
9. Not read by this run: the Rogue and the Skeleton; the still and walk rungs; `fight` and `fights`, and whether sparring's commitments cover theirs; 480 Hz; profiles; any reel; any search or training from a fit. A defect met on the way (a trial faulted, a world refused; not a file that lands few, which is the measure, nor a control that does not hold, which is 5's) is fixed at its cause, in a commit of its own, under `npm run check`, `npm test` and `npm run build`. Where the fix is under `src/`: before it, `node scripts/fingerprint.mjs --json .tmp/punch-readings/fingerprint-before.json`; after it, `--compare` with that file, its lines read, not its exit code alone. No pose moved and no case new or gone: the run goes on. Otherwise the fix stays committed, nothing more is played, and the run reports.
10. Stops when each of the nine files has its reading, at a control that does not hold (5), or at the budget; no next item: no variation is built, nothing is searched, and no file's reading is acted on. One report covers: each file's landings beside the drive's, how many starts only one lands and its p, its damage ratio and interval, falls, life taken and value; whether the control held and what was fixed for it; the spans chosen and how well each fit copies the network on the training half; the seconds a side of a `--bar` took; everything done beyond the question; what is unchecked, the span chooser and the solve among it where only the fits' own readings exercise them. `.tmp/punch-readings/` is deleted once the report is written.
