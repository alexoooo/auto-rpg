# Mind data: loaded per use, packed per kind

## Direction

The game is to be playable on a phone, with 100 or more actions. Today every page that opens the
arena, the crypt or the lab downloads every mind's data, used or not: the production build's
`models-*.js` chunk is 26.4 MB (11 MB gzipped), and about 25 MB of it is four JSON files.

| File | What it is | Size | Who uses it |
|---|---|---|---|
| `assets/research/research-rise.json` | Research rise: three recorded get-ups, a club get-up, 104 measured response tables | 19.3 MB | Only a mind that lists the `research-rise` sub-mind |
| `assets/research/research-rise-unshod-warrior.json` | Research rise: two more get-ups for the empty-handed Warrior without soles | 3.2 MB | The same |
| `assets/core/learned-rise.json` | A ReLU network, 99-256-256-15, 95,247 numbers | 2.0 MB | Built by every Warrior and Rogue `stand-up`; run only if `learned-rise` is listed |
| `assets/core/learned-run.json` | A ReLU network, 47-256-256-12, 81,164 numbers | 1.7 MB | Only the `learned-run` locomotion |

A get-up's motion, kept at 30 Hz, is tens of KB, and a network is about 0.2 MB. With data loaded
per use and stored as small integers, 100 actions are some megabytes on the server and the
handful a bout fields on the phone.

Two changes, in this order:

1. **Per use** (chunks 0 and 1, now). A screen asks which data its minds need and loads it
   before it builds them, under its loading overlay. Nothing a bout does changes.
2. **Packed** (chunks 2 and 3, when the next action that carries data arrives, or a phone build
   fields a mind that reads data). Data is shipped as binary arrays, each in the encoding its
   kind can bear, compressed, and decoded into the same plain values the minds read now. A
   precision is a change of behaviour, measured before and after.

Chunk 4 waits: once loading is per use, Research rise's tables download only for a player who
picks that experimental part.

### First: what a phone can step

Download size is one half of playable on a phone; the other is what a step costs there. Before
chunk 2, time the same Arena bout's steps (`__arena.world.step()` in a loop, through remote
debugging) in the owner's phone's browser and the desktop's, and a Crypt hall the same way,
naming the device, engine and rate. It takes minutes and says which constraint binds. If the
step is the constraint, that is the next work, ahead of packing; `research/step-time.mjs` then
says where the step goes.

### With Ratings

The data a case's minds read is part of what the case plays. When Ratings draws a case's code by
its import closure (its step 12), the files `treeData(config)` names join that code, since a
store's loads are not static imports. A browser worker that plays cases (its step 14) calls
`loadData` itself: the store is loaded once a realm.

Every check below runs in minutes; none is a battery read for its own sake
([framework](2026-10-21-framework.md), Compute).

### The owner's decisions

- Brotli is acceptable; no algorithm or representation is fixed.
- Recomputing on the device to save transfer is a good trade.
- Precision is chosen per kind of data: a network's weights may be smaller than a motion's
  angles.
- Art textures are out of scope (a separate task).

### What must not move

- Chunks 1 and 2 change no bout: the fingerprint, with chunk 0's cases, names no moved case, and
  chunk 2's decoded data equals its source to the bit. Chunks 3 and 4 move the cases of the data
  they touch, and their commits name them.
- Construction stays synchronous: `new Duel`, `enlist`, `createMind`, `createBody`'s sub-minds and
  the Dungeon's mid-run `wake()` (inside a world step) cannot await. Data is loaded before.
- A mind built without its data fails when it is built, naming the key and how to load it. It
  never runs with a substitute and never fails later, mid-bout.

### Measured so far (Node, the bundled JSON, `node:zlib` at maximum settings)

| Research rise's three recorded get-ups (227,500 numbers) | Raw | gzip | brotli |
|---|---|---|---|
| JSON text | 3,451 KB | 1,509 KB | 1,273 KB |
| 32-bit floats | 889 KB | 625 KB | 586 KB |
| 32-bit floats, byte planes | 889 KB | 519 KB | 497 KB |
| 16-bit, steps of 0.001 | 444 KB | 250 KB | 195 KB |
| 16-bit, steps of 0.001, change from the previous frame | 444 KB | 187 KB | 156 KB |

- The first get-up's angles kept every 4th frame (30 Hz) and interpolated linearly are off by
  0.06 degrees on average and 5.7 degrees at worst (around contacts).
- The 104 response tables do not compress by structure: twenty principal components leave 43 %
  of them unexplained.
- Storing 64-bit floats exactly saves almost nothing over brotli'd JSON (6.7 MB for Research
  rise), so a real gain requires a lower precision.

## Chunk 1: load mind data per use

A toolkit change, on its own branch, read against main with the fingerprint.

### The store: `src/core/data/store.ts`

Outside the mind folders, so it may load; inside the core, so minds may read it.

```ts
/** **Mind data**, by key: loaded before the minds that read it are built, and read synchronously after. */
export type DataKey = "learned-rise" | "learned-run" | "research-rise";

interface DataOf {
  "learned-rise": LearnedRiseData;
  "learned-run": LearnedRunData;
  "research-rise": ResearchRiseData;
}

const LOADERS: { readonly [K in DataKey]: () => Promise<DataOf[K]> } = {
  "learned-rise": () => import("../../../assets/core/learned-rise.json", { with: { type: "json" } }).then(m => deepFreeze(m.default)),
  "learned-run": () => import("../../../assets/core/learned-run.json", { with: { type: "json" } }).then(m => deepFreeze(m.default)),
  "research-rise": researchRiseData,
};

export const DATA_KEYS = Object.freeze(Object.keys(LOADERS) as DataKey[]);

/** Load `keys`; a key loads once a realm, and a failed load can be asked again. */
export function loadData(keys: Iterable<DataKey>): Promise<void>;

/** `key`'s data; throws, naming `loadData` and `tests/harness/preload-data.mjs`, when it is not loaded. */
export function dataOf<K extends DataKey>(key: K): DataOf[K];
```

- `researchRiseData` is in `src/core/data/research-rise.ts`, not in `research.ts`, so the store
  and `research.ts` import no cycle. It imports both research files dynamically, parses each
  `payload`, deep-freezes, and merges the unshod Warrior's entry as `research.ts`'s top level does
  now (`bundle`, `additions`, `unshodWarrior`). `research.ts` keeps no top-level parse.
- Vite splits each dynamically imported JSON into a chunk of its own; Node imports JSON natively.
  `tests/core-boundary.test.mjs` walks literal dynamic imports (`ts.preProcessFile(..., true,
  true)`) and admits JSON under `assets/` (`isData`), so the boundary needs no change. tsc
  (`module: ESNext`, `moduleResolution: bundler`) accepts the import attributes.
- The loaded map is a cache of frozen data, not a bout's state: it holds no step-to-step change.

### What a config needs: `treeData`

Each part says what it reads, beside `faults`, and the catalog walks the tree as `treeFaults`

## Chunk 2: the packed format, lossless

The format and its loaders land with exact encodings only, so no bout moves.

### The file

```
"ARPD"  u8 version (1)  u8 compression (0 none, 1 gzip, 2 brotli)  then, compressed:
  u32 header length, LE | header (UTF-8 JSON) | zero padding to 8 | blocks
header = { "tree": <the data, each packed part replaced by { "$": index }>,
           "blocks": [{ "encoding": ..., "length": n, "offset": bytes, ... }] }
```

Packed parts:

- **Array**: a homogeneous array of numbers, with `shape` for a matrix (a network's `weights`).
- **Table**: an array of objects, such as a motion's frames, stored as columns. Each column is
  one key path (`angles.0` to `angles.34`, `loads.head`, `handPoses.left`). A key a row lacks is
  a column's absent mark, so frames whose kinds carry different keys (`muscles` and `host`) keep
  them. A column is encoded on its own and may be a delta along the rows. The decoder rebuilds the
  objects with their keys in the source's order. This is what holds the frames of 23,788 small
  arrays in a few hundred columns, and what makes change-from-the-previous-frame expressible.
- **Exceptions**: a numeric column's values that are not numbers, as `(row, value)` pairs.
  Research rise's frame `velocity` mixes numbers with the strings `"+inf"` and `"-inf"`
  (`reference-types.ts`), and `reference-path.ts` branches on `typeof v === "number"`, so the
  strings are restored as strings, never as `Infinity`.

| Encoding | Bytes a value | Decoded value |
|---|---|---|
| `f64` | 8 | exactly the stored double |
| `f32` | 4 | the float widened, exactly |
| `i16` `{ step, delta? }` | 2 | `q * step`; with `delta`, `q` is the running sum of the stored integers |
| `i8` `{ scales }` | 1 | `q * scales[row]`, one scale per row of a matrix |
| `u8` `{ labels }` | 1 | `labels[q]`, for strings such as a hand's pose or a frame's `kind` |

- Decoding uses `*` and `+` only, so every JavaScript engine decodes the same doubles
  (`EXACT_MATH`).
- The decoder returns plain arrays and objects, so the minds read what they read now.

### Files and code

- `src/core/data/packed.ts`: `unpack(bytes: Uint8Array): unknown`, pure, over decompressed bytes.
- `scripts/pack-data.mjs <key>`: reads the key's source JSON and writes `public/data/<key>.arpd`.
  It picks a table for an array of objects and an array for an array of numbers, with
  per-column encodings from a table in the script: `f64` and labels throughout in this chunk.
  It also writes `assets/core/learned-run.meta.json`.
- The source JSON files stay in the repository as the packer's input, and
  `scripts/bundle-research-rise.mjs` keeps writing them. `tests/core-research-rise.test.mjs`
  imports both research files directly. `tests/data-budget.test.mjs` keeps them out of the bundle.
- The store's loaders read `public/data/<key>.arpd` through a reader the host gives,
  `loadData(keys, read)` with `read: (file: string) => Promise<Uint8Array>` returning decompressed
  bytes:
  - Browser, `src/data-read.ts`: `fetch(publicAssetUrl("/data/" + file))`, decompressed with
    `DecompressionStream`.
  - Node, `tests/harness/preload-data.mjs`: `readFile` and `node:zlib`.
  - The core calls neither `fetch` nor `DecompressionStream`.
- The extension is `.arpd`, not `.br`, so no server applies `Content-Encoding` and the browser
  always receives the compressed bytes.
- `.gitattributes`: `*.arpd binary`, since this clone has `core.autocrlf` on.
- `AGENTS.md`, "The core reaches only itself": add that mind data is read through
  `src/core/data/store.ts`, from bytes its host supplies.

### The compression byte

Check `new DecompressionStream("brotli")` in current Chrome, Firefox and Safari, the owner's phone
among them. If every target has it, use brotli. Otherwise use gzip (supported everywhere), or
brotli with a decoder shipped beside the store if its size (tens of KB) is worth the difference
(about 15 % at these sizes). The header's byte keeps the choice per file.

### Verify

- `tests/core-packed.test.mjs` (fast):
  - Each encoding and the table round-trip through the packer's writer and `unpack`: to the bit
    for `f64`, `f32` and labels, within half a step for `i16` and `i8`.
  - A truncated file and an unknown version are refused, by name.
  - Each packed file in `public/data/` decodes to exactly its source JSON (every number by
    `Object.is`, every string and key order equal). For a lossless file this proves that no
    bout moves, whatever the fingerprint covers. Chunk 3 narrows this check to the columns it
    leaves exact.
- Fingerprint, with chunk 0's cases: no moved case.

## Chunk 4: Research rise's response tables (waits)

Only when Research rise is to be fielded on a phone. 12.5 MB of Research rise is the response tables of its first get-up: 104 samples, each a
`columns` and a `coastColumns` matrix, 35 by 80. They are measurements of the body's own physics.
The script that measured them is not in the repository: `bundle-research-rise.mjs` packages
gzipped references made elsewhere. So recomputing them on the device is not yet easy.

1. Measure Research rise with its first get-up as a `path` controller, like the other two (no
   responses), on the three tests in chunk 3's Research rise row. To read it on the owner's
   64-fall target as well, `research/rising-bed.mjs`'s `--sub` (now `support-recovery` or
   `stand-up`) first gains `research-rise`: a research change of its own.
2. If it holds, drop the response tables: Research rise falls to a few hundred KB.
3. If it does not, recompute on the device. First recover from `responsePolicy`
   (`src/core/mind/rise/reference-response.ts`) and the references' history what `columns` and
   `coastColumns` each measure: the response to a nudge of each of the 35 muscle speed requests,
   read as the change of the 80 features `responseFeatures` reads, and the response coasting
   after it. Then, at each sampled step:
   - fork the world (`saveState`/`loadState` and `world.physics.save()`),
   - nudge each request in turn,
   - read both matrices.

   Time it on a phone-class CPU. If it is too slow at a bout's start, compute it once per device
   and keep it in the browser's storage (IndexedDB), keyed by the build's identity.
