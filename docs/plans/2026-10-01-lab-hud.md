# The lab's HUD: six sections, filled through one control vocabulary

## Context

The lab screen has one panel holding everything. The owner wants one HUD, the same in every
scenario, in six collapsible sections, with the character split into Body, Items and Mind, and a
log of what the mind decides:

| | left | middle | right |
|---|---|---|---|
| **top** | Scenario (configuration) | View | Character: Body, Items, Mind |
| **bottom** | Readout (numbers, legend) | Controls (keys, actions, Restart) | Thinking (the mind's log) |
| | the replay bar, full width | | |

It must be built to grow: no shared cross-scenario markup or switch, no god-function, nothing
hard-coded twice, and no authored prose beyond what exists.

What stands in the way today, and goes:

- Each scenario's markup is in the shared `index.html` template behind `data-for`, reached by
  global ids (`need("s-phase")`).
- Options are written twice: as buttons in HTML and as lists in TS (`MODELS`, `LAB_RATES`,
  `LAB_CAMERAS`, `TRACKS`, ...); legend colours as hex in HTML and `Color3` in the scenario.
- `bootLab` (`src/lab/main.ts`) wires every control itself, a dozen copies of one loop.
- Each of the four modes makes and drives its own body (`createBody`, `driveBy`), so anything
  given to a body (balance, a mind, a log) would be threaded through all four.

## Design

**1. Controls are built, from the lists the code has** -- `src/lab/hud/controls.ts`:

```ts
interface Control { readonly element: HTMLElement; refresh(): void }
interface Option<T> { readonly value: T; readonly name: string; readonly title?: string }
export function choice<T>(label: string, options: readonly Option<T>[], selected: () => T, pick: (value: T) => void): Control
export function action(name: string, run: () => void, title?: string): Control
export function quantity(label: string, range: { readonly min: number; readonly step: number }, value: () => number, set: (value: number) => void): Control
export function readings<K extends string>(rows: Readonly<Record<K, { readonly name: string; readonly unit?: string }>>): { readonly element: HTMLElement; write(values: Readonly<Record<K, string>>): void }
export function legend(marks: readonly { readonly colour: Color3; readonly name: string }[]): HTMLElement
export function keys(hints: readonly { readonly keys: readonly string[]; readonly does: string }[]): HTMLElement
```

The pressed state, blur on click and the existing classes (`.models`, `.label`, `dl`, `.swatch`,
`kbd`) live here and nowhere else. `readings.write` takes the whole record, so a row left out is a
type error. A legend's swatch is the mark's own `Color3`.

**2. A scenario hands the shell its panels** -- `LabScenario` (`src/lab/lab-scenario.ts`) gains

```ts
readonly panels: Readonly<Partial<Record<"scenario" | "readout" | "controls", readonly HTMLElement[]>>>;
```

built with the vocabulary in its own module (anything else, like the Routine's strikes table, is
just another element). The shell appends each list to its section. `data-for`, the per-scenario
ids and every option button leave `index.html`: the lab template is the canvas, six empty
`<details class="section" data-section="...">` with a one-word `<summary>`, and `#transport`.
Adding a scenario is its module, its `SCENARIOS` entry and its line in `main.ts`'s `SCENARIO`.

**3. The shell composes sections** -- `src/lab/hud/`, each a module that fills its slot and
refreshes from the one state (`LabAddress`):

```ts
interface Section { refresh(shown: LabAddress): void }
interface LabPage { readonly shown: LabAddress; load(next: LabAddress): void; remember(next: LabAddress): void }
```

- `sections.ts`: the six slots by name, and their collapse memory (`localStorage`, as
  `src/audio/game-audio.ts` guards it). Pure halves exported for Node:
  `collapsedFrom(text, names)`, `collapsedText(sections)`.
- `scenario-section.ts` (name, way back, rate), `view-section.ts` (view, camera, projection),
  `character-section.ts` (Body, Items, Mind), `transport.ts` (pause, nudge, timeline, rate, clock),
  `thinking-section.ts` (the log).

`bootLab` keeps the stage (engine, scene, lights, ground), `load`, the keys and the render loop.

**4. One place makes and drives a lab body** -- `src/lab/actor.ts`:

```ts
export interface ActorOptions {
  readonly assist?: AssistCeiling;                 // BodyOptions.assist
  readonly stance?: StanceTuning;                  // BodyOptions.stance
  readonly allows?: (recipe: Recipe) => boolean;   // filters the repertoire the skills get
  readonly mind?: (script: Tactics) => Tactics;    // what drives, given the scenario's script
}
export interface Actor { readonly body: Body; drive(script: Tactics, options?: SkillOptions): Skills }
export function labActor(built: BuiltBody, world: World, options?: ActorOptions): Actor
```

The modes take an actor instead of making a body: `startStance(actor)`, `startRun(actor, track)`,
`startRoutine(actor)`, `throwBlow(actor, strike, distance)`. None of them knows of balance, minds
or logs. Their callers in `tests/`, `research/` and `scripts/` pass `labActor(built, world)`
(`core-routine-battery.mjs` passes its tuning as `stance`). With no options the actor passes the
script and `REPERTOIRE` through untouched, so `scripts/fingerprint.mjs` reads the same.

**5. A mind is an entry in a list** -- `src/lab/minds.ts`:

```ts
export interface LabMind { readonly id: string; tactics(script: Tactics): Tactics }
export const LAB_MINDS: readonly LabMind[] = [
  { id: "script", tactics: (script) => script },
  { id: "guard", tactics: () => ({ name: "guard", decide: () => standIntent() }) },
];
```

The chooser lists the ids. Its actions are derived, not listed: for each hand,
`recipeFor(REPERTOIRE, spec, hand)`, one switch per distinct `recipe.held`, shown by
`strike.name`. A barred `held` goes to `ActorOptions.allows`; with no recipe the strike skill has
no blow for that hand and the body guards, in every scenario by the same path.

**6. The log says the code's own words** -- `src/lab/mind-log.ts` (no DOM, `import type` from core):

```ts
export interface MindLog { note(time: number, text: string): void; readonly revision: number;
  upTo(time: number, count: number): readonly { readonly time: number; readonly text: string }[] }
export function createMindLog(capacity?: number): MindLog
export function logged<T extends Tactics>(tactics: T, log: MindLog): T
```

`logged` delegates (`Object.create(tactics, { decide })`), and notes a line when it differs from
the last of its kind, at `sight.view.time`: `move 0.30 0.00` / `stand`; `right attack` /
`right guard` (`HandAction.kind`); `strike chamber <Strike.name>` (`StrikeReport.phase`, nothing
for null); `fallen`. No turn line (per step the asked turn is noise or silence, and it depends on
the rate). The page composes it at the actor: `mind: (script) => logged(chosen.tactics(script), log)`.
The Run's and the Routine's Doing rows go from the Readout: they are the script's, and the log
says it for whichever mind drives.

**Address** (`src/lab/scenarios.ts`): `balance: number | null` (null is the character's own, as
`DuelRecipe.balance` falls back in `src/arena/duel.ts`), `mind: string` (an id of `LAB_MINDS`),
`barred: readonly string[]` (`held` names found in `REPERTOIRE`). Changing any is a `load`.

## Chunks (each lands green and is committed)

1. **Vocabulary and scenario panels.** `hud/controls.ts`; each `*-scenario.ts` builds its panels
   and returns them; the shell mounts them in `#panel` as it stands. `data-for`, scenario ids and
   scenario buttons leave `index.html`; labels move as they are (`TRACKS` gains `name`). No visible
   change.
2. **Sections.** The template becomes the six sections and the transport; `hud/sections.ts`,
   `scenario-section.ts`, `view-section.ts`, `character-section.ts` (Body: model; Items: hands,
   wears), `transport.ts`; shell options built from their lists; `style.css` (below); Space on a
   focused `<summary>` is its own. The re-layout is visible here.
3. **Actor and Balance.** `actor.ts`; modes take an actor; callers updated; `balance` in the
   address; Body gains `quantity("Balance", ...)`; `load` gives the actor
   `balanceCeiling(points, balancePoint(rulebook()))`.
4. **Mind.** `minds.ts`; `mind` and `barred` in the address; the Mind sub-section (chooser,
   action switches) refreshed from body and items.
5. **Thinking.** `mind-log.ts`, `thinking-section.ts`; the Blow's moment takes its time from
   `body.view.time` like the other three, so the shown time cuts the log exactly; Doing rows
   removed from the Run and the Routine (and `Routine.doing` if nothing else reads it).

`style.css`, chunk 2 (the `<details>` is the scroller; only a column's last section shrinks):


The `#panel` rules go; `#lab-select > a, #panel > a` becomes `#lab-select > a, #to-scenarios`
(`<a id="to-scenarios" href="?play=lab">` keeps exactly those attributes, in the Scenario summary).

## Text

Nothing new is authored. Labels, legend names and key hints move as they are; summaries are one
word; log lines and mind names are identifiers and values. Comments: one line a construct where
the code does not say it. Documents: `README.md` "The Lab" and `docs/architecture.md`'s lab bullet
corrected in place, no longer than now; `SCENARIOS`' stance `line` loses "from the panel".

## Tests

- Node, whole records, each mutated red once: `lab-sections` (the two pure functions),
  `lab-scenarios` (the address with its three new fields), `lab-actor` (no options: the script and
  `REPERTOIRE` pass through, same object; `allows` leaves a barred hand `recipeFor` null; at 5
  points the Stance holds a shove that fells it at 0; under `guard` the Routine throws nothing and
  stays put), `lab-mind-log` (rolls, cuts at a time on both sides, exact entries for scripted
  tactics, for 20 s of the Run's circle and for the Blow's phases in order).
- `tests/app.test.mjs`: the lab template holds exactly the six section names, each a `<details>`
  opening with a `<summary>`.
- `node scripts/fingerprint.mjs` equal before chunk 3 and after chunks 3, 4 and 5.
- Each chunk: `npm test`, `npm run check`, `npm run build`, the line-ending gate, then a reviewer
  told to refute the diff, then the commit.

## Verification in a browser

On a preview server of my own (another port, killed by PID), each of the four scenarios:

- after chunk 1 the page looks and behaves as it does now;
- after chunk 2: six sections where the table says, each collapsing and staying so across a
  scenario change; Space pauses after a summary is clicked or tabbed to; a drag between sections
  orbits; nothing runs off the page at 1280 and 1920, and it stacks under 1100;
- Balance 5 holds the Stance through a shove that fells it at 0; `guard` stands every scenario
  still; barring the club's blow leaves the Routine walking and not striking; the address keeps
  all three across a reload;
- the log writes a walk while W is held and the Blow's phases, and shortens when scrubbed back.
