# Complete layer contracts and invariant ownership

## Goal and scope

Make the declared boundaries hold through actual construction, execution, observation, restoration
and evidence. An independent component uses published contracts without adopting a stock provider's
private representation. A valid body keeps its declared identifiers and capabilities throughout
the stack. Each owner validates what it consumes, saves what it retains and disposes what it owns.

The [fresh audit](../analysis/2026-11-05-fresh-layer-boundary-audit.md) supplies the failure recipes
and affected constructs. Its [file ledger](../analysis/2026-11-05-fresh-layer-boundary-files.md)
supplies the reviewed producers and consumers. All 56 confirmed findings and six unresolved
questions are in scope, including each related instance within a grouped finding. Correct any
additional violation exposed along those paths in the same work. Track closure against current
contracts and evidence; finding counts alone do not establish completion.

## Design rules

- Reuse owner predicates, configured declarations, state utilities and existing lifetime helpers.
  Share a helper where actual consumers share a rule; keep local acquisition and cleanup local.
- Resolve configuration once at its owner. Admission, construction, dependency identity and
  inspection consume that resolved meaning rather than reconstructing it independently.
- Return a named refusal for unsupported input before acquiring dependent resources. Keep internal
  defects as errors and catch them at reporting boundaries with their original messages.
- Keep body identifiers opaque to general code. Resource kinds, motor goals and anatomical meanings
  have canonical declarations at their respective owners. A shared string constant does not make
  an implementation assumption general.
- Prefer explicit data and direct composition. Parameterize a genuinely reusable protocol, or keep
  a specialized protocol with its provider. Add an extension hook only where a real consumer needs
  it; remove an unsafe optimization when that is the simpler correct solution.
- Put durable values in the existing state graph and freeze shared constants when publishing them.
  Compare detached command/report values wherever a producer can retain and mutate an object.
- Keep partial work and failures explicit. Missing trials, invalid fixtures, worker faults and
  incompatible identities retain their meaning through every reader and reporting boundary.

## Sequencing and overlap

Begin with bounded reproductions of the audit's failures. Repair the evidence admission, subject
metadata and coverage paths needed for trustworthy comparisons, alongside fatal worker settlement
and the zero-pace hang. Establish current case keys and explicit missing/faulted outcomes before
using the table or saved records as a baseline. These checks need no training or broad gameplay run.

Establish capability/resource and provider contracts next, including the recovery requirement and
gait-sharing questions. Update declarations, constructors, validators, state, editors and transport
consumers together. Fix shared immutable values and compatible physics restoration early; all

active editor. Concrete admission, geometry and command-value repairs follow their owning

resulting implementation after these producer/consumer changes join.

## Capabilities and public protocols

- Use the canonical open `Requirement` type throughout part traversal. Check each requirement
  through its capability owner at admission; keep the selected factory's declarations consistent
  with the constructed controller. Resolve Q-REQUIREMENTS and Q-MOTOR here.
- Give action resources explicit kinds, separating physical segment/channel claims from logical
  services and configuration actuators. Keep any compact key encoding private to the resource
  compiler. Valid segment names cannot collide with service names or generated prefixes.
- Derive support-chain claims from the declared bearing geometry and joint/channel paths,
  independently of optional effector actuators. Compile the same footprint for admission conflicts
  and write validation. Distinguish physical technique bindings from the actuators a command needs.
- Keep the profile provider's `Seen`, threat calculations and profile tables with that provider.
  Give reusable percept/prediction roles an explicit input protocol and compatibility declaration,
  following the existing Option/chooser protocol pattern. Validate compatibility before invoking
  callbacks; the lookup's type erasure cannot authorize an unchecked provider cast.
- Use own-key membership and a safe plain record for sensed identities, preserving state-codec
  support. Exercise ordinary names and inherited JavaScript property names through registration,
  observation and removal.

Verify a real support without an effector, a segment named like a logical service, an augmented
requirement and an independent perception input. Exercise their actual assembly and consumers.

## State and immutable values

- Construct each configured aim once and attach its state to the assembled skills, including the
  default public assembly path. Put evaluation cue indices, orders, shove/stand progress and
  accumulating reader values in their owners' state objects and aggregate those roots explicitly.
  Expose restoration only once the entire supported evaluation path can resume faithfully.
- Include immutable world conditions, including gravity and configured rate, in physics save
  compatibility. Reject incompatible loads before mutating the receiver. A successful load keeps
  its public settings consistent with the restored solver.
- Deep-freeze completed equipped specs and nested recovery tuning before caching or publishing
  them. Protect the shared up vector at runtime and through its read surface. Resolve Q-DATA at
  the loading boundary rather than relying on undocumented behavior of particular loaders.
- Put effector-goal equality at the goal's owner and compare its complete semantic value. Preserve
  response, firmness, unbending and moving-frame fields through command delivery and restoration.
  Keep the comparison allocation-conscious without dropping fields.
- Retain detached previous Orders and gait-report values for change detection. Live getters or
  in-place producer changes must cause the appropriate decision or transport update. Compare the
  same value representation that the receiver consumes.

Verify fresh-instance continuation and in-place restoration immediately before an aim update,
queued cue or changed command. Compare whole observable results, not only final poses. Check
mutation isolation by reading the same cached recipe again in the same realm.

## Admission and physical geometry

- Resolve stock records plus partial overrides at each concrete owner, then apply the complete
  settings predicate used by construction. Separate numeric configuration faults from body
  applicability. Cover guard null/shape/range faults, staged posture channels, stomp durations,
  paw gait speeds/stride durations and bite path durations.
- Make human guard and strike implementations explicitly require or resolve the hand configuration
  meanings they use. Generic configuration commands continue to accept body-declared names.
  Check every related guard, straight-punch, swing and held-strike path named by BH-05.
- Validate a paw's declared support point and requested patch shape. Validate the joint frame's
  pairwise orthogonality before constructing it; do not silently reinterpret malformed axes.
- Implement correct convex clearance at the geometry owner: capsule/polytope closest distance,
  including edge and corner cases, and the full separating-axis set for hull pairs. Reuse existing
  geometric primitives where suitable. Preserve actual overlap refusals and numerical tolerances.
- Draw a zero-span capsule using its spherical geometry, consistent with the physical adapter.
  Derive fallen-body navigation extents from observed geometry at its actual elevation.
- Treat zero attainable travel speed as no finite movement option while preserving legitimate
  stationary choices. Bound pressure integration by a deterministic sample count and meaningful
  prediction horizon, including tiny positive speeds. Preserve zero as a valid pace order.
- Define finite profile behavior for immediate failed trials. Keep such outcomes as failures;
  avoid zero-cycle division and fabricated positive durations. Refuse a rate that the profile
  cannot define if a finite failure rate is not meaningful under its contract.

Reproduce both sides of each admission boundary: supported inputs execute, unsupported inputs
return the owner's reason before allocation. Reuse the audit's separated shapes, malformed joint,
custom configurations, elevated body, zero-duration trial and zero/tiny-pace cases.

## Construction and pending work

- Use local `try/finally` for a single acquired resource and the existing construction scope for
  multiple acquisitions. Register rollback as each resource is acquired and transfer ownership
  only after the complete result is usable. Keep this bookkeeping out of simulation state.
- Cover partial core body construction, Duel and TeamBout members/hooks, standalone technique
  trials, learning-environment starts and all browser benchmark protocols. Check technique and
  predecessor applicability, pooling save/load support and layouts before invoking dependent work.
- Dispose the temporary hosted Mind as well as its built body and world during local Dungeon
  warming, on success and failure. Preserve ownership of caller-supplied worlds.
- Make worker startup own the completed stage before reading or posting initial presentation.
  Catch the complete startup continuation, report the original fault and dispose the stage.
- Define a pool's open, stopping and closed states explicitly. Every accepted job settles once;
  close rejects unfinished work and later submissions. Startup loss, post failure, worker error,
  unexpected exit, callback failure and timeout all use the same terminal ownership rules.
- For fatal pool failure, stop admission, clear timers, settle pending jobs and await worker cleanup
  before returning. Preserve recoverable per-job replacement where the protocol already supports
  it. Reuse `workerJobs` or the existing pool where its semantics fit; keep environment-specific
  transport behind its adapter rather than building another pool framework.
- Apply those rules to evaluation lanes, fingerprint/righting tools, rollout and league pools,
  and every recovery pool listed under RF01. Validate worker counts before scheduling. Disposal
  attempts every owned stop even when notification to one worker fails; reporting preserves the
  initiating error and makes any cleanup failure visible.

Use bounded lifecycle probes with acquired/disposed and submitted/settled counts, including failure
after a completed sibling acquisition. A terminated worker alone does not establish job settlement.

## Exact transport counters

Take reply-ring offsets modulo the capacity in BigInt before converting the bounded result to
Number. Define one rollover-safe completion-sequence representation for producer and waiter.
Keep outstanding work bounded so completion comparisons remain unambiguous, including when one
batch advances many seats. Preserve the existing drain/backpressure behavior. Exercise both counter
boundaries directly and verify FIFO payloads and completion without waiting for long-running bouts.

## Evidence contracts and consumers

- Normalize each subject once into its full execution description: value, component declarations,
  body restrictions and character attributes. Scheduling, recorded identity and previous-subject
  reconstruction consume it across every evaluation adapter. Legacy records whose execution facts
  cannot be recovered remain explicitly incompatible for that use.
- Identify standalone skill and technique subjects through declared component roles and configured
  dependency traversal. Include selected aim data alongside executor data in skill identity,
  retaining each loader's body-specific identity rule. Avoid another list of recognized ID prefixes.
- Validate whole record headers and rows at the record owner. Put cross-record duplicate agreement
  in one shared admission/indexing path consumed by CLI loading, history pools, Ratings case lookup
  and Arena reels, including previous-trial selection. Equal duplicate rows may share a key;
  conflicting rows report their origin and remain unusable.
- Derive required case keys from the actual protocol and complete subject description. Merge
  compatible partial records and schedule missing or retryable failed cases. Keep current identity,
  coverage and outcome distinct: publish met only with all required successful trials satisfying
  their bar. Handle fault/null readings explicitly and preserve available partial evidence.
- Record that Cover's intended attack fixture is reached independently of whether contact occurs.
  Read the attack's actual execution event at its owner; legitimate avoidance can remain untouched.
  A fixture that never attempts its attack receives an explicit invalid/unreached result.
- Refuse combat evidence publication when source identity changes before, during or after a trial.
  Preserve faulted work for diagnosis without reusing it as a successful compatible trial. Do not
  relabel historical rows or regenerate expectations to conceal incompatibility.
- Report the actual built engine and received worker simulation cost. Keep totals and step counts
  together and exclude zero-step divisions from per-step statistics. Pair locomotion rows using
  every scenario-defining field, including equipment and duration, and reject ambiguous duplicates.

Verify the whole producer-to-reader path with restricted custom subjects, standalone components,
changed aim data, partial and faulted records, conflicting duplicates, an unreached attack and a
source mismatch. Assertions on a correct CLI helper alone do not establish browser/reel behavior.

## Validation and completion

For each landable change, name its contract, related finding IDs, consumers and narrow failure
recipe. Add a retained test only where a concrete observed regression lacks adequate existing
coverage, and explain it in the [test inventory](../../tests/README.md). Keep checks at the owning
layer; compare whole returned records and observable commands, including failures.

Run the [gates required by the change](../../AGENTS.md#doing-the-work). Preserve exact fingerprints
for behavior-preserving slices. Corrected behavior names its affected cases and receives the
appropriate paired readings; measure performance only for the allocation question or a speed
rewrite. Respect the existing run budgets, retain reusable rows and report any remaining setback.
Visible changes receive a brief browser check. Skill claims require watched drill evidence, and
only the owner accepts a rung.

Before completion, re-read each affected file against the audit criteria and follow every changed
public contract through declarations, assembly, validation, commands, state, transport, inspection,
research and evidence. Exercise an independent provider, a custom resource identifier, physical
supports without actuators, a memoryful aim and an incompatible motor through the real public APIs.
Use the existing Node/browser and local/worker paths where they consume the changed contract.

Close every confirmed obligation and resolve every question with its evidence. Reconcile related
findings by their actual contract so one corrected caller cannot conceal another broken instance.
Keep newly discovered violations in scope. Completion requires the intended separation to hold in
the resulting code, current documents to describe it, and all required checks to pass; a green
boundary scan or an unchanged fingerprint establishes only its own property.

Commit each landable change on main without pushing. Keep status in the roadmap and current
contracts in the architecture. Remove this plan and the resolved audit documents when the work
lands, preserving the implementation evidence in commits and the appropriate retained diagnostics.
