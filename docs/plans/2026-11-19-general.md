# General, not ad hoc

**The goal, in the owner's words, 2026-11-19** (through the reviewing session):

> This is a recurring failure pattern. I always ask for general and consistent changes, but they
> are added as an ad-hoc hard-coded hack. Is there something in this repo that pushes you to do
> that?

Told six causes and four changes:

> I want all of this. But also, I want the instructions and tooling themselves to be simple and
> general -- I don't want the documents or tools to be clean and simple also.

The last clause is read as "the documents and tools are to be clean and simple also" (the
reviewing session's reading, told to the owner). Before it, the owner's standard: "the most
important thing is to maintain and even increase the code quality of this project. we need to
implement everything in the most simple and general way that we can"; and of the back step's
preset, "I always want everything to be just a skill. I don't want any ad-hoc hard-coded hacks."

## The changes, in order

1. **`AGENTS.md`, at its top**: the owner's standard in their words, and one rule: a new
   capability enters by the same config path as those already there; work not yet kept lives in
   a worktree, never on main behind a helper, a preset or a flag.
2. **The code recipe's "An experiment is a kind behind its contract, selected by a config, or it
   is deleted"** is replaced: an experiment is tried in a worktree and lands as the general thing
   or is dropped; nothing stays selectable because it was once tried. Then what that rule left
   behind: Initiative "in the picker unset", the line's-end kinds no Mind uses, and whatever else
   is found.
3. **The precedents**: every `offered: false`, every `stage:`, every "not the game's" (the presets
   in `bare`, `walker`, `option-prior`, `option-drill`; `chooser.ts`'s "By rank", `objective.ts`'s
   "Reach a place", `recovery/shared/staged/records.ts`). Each is a real need said in a line (a
   drill's Mind is one) or a leftover removed. Clear leftovers go; a judgement goes to the owner
   with a recommendation, and the work goes on.
4. **The side door costs what the general way costs**, the door removed rather than guarded:
   where a list is written by hand beside a registry (the Option Mind's Options beside the
   registered Option parts, the gaits beside Move's), the registry is the list, so a skill
   registered is a skill in the Mind. A test only where structure cannot do it. And the general
   change made cheap: one command re-reads what a change to the Mind moved (the saved rows, the
   fingerprint's cases, bout by bout).

## How

- **Each document touched is simpler and more general after**: each thing said once, a general
  rule in place of the special ones it covers, nothing that steers no one. The owner, 2026-11-19:
  "And just to clarify, for AGENTS.md, word or line count are not the primary metric. I want
  simplicity and generality, which typically means shorter, but that's not my goal." So no line
  is cut or squeezed to make a count, and none a document needs is held back because it would
  grow; the same for the recipes and the approaches. Line counts are a reading, not a bar
  (`AGENTS.md` 61, the code recipe 97, the skill recipe 503, the approaches 344 at the start).
- **The tools the same**: no new script where a command can take the case; scripts and flags in
  `research/` and `scripts/` that exist for one finished reading go, each named in its commit.
- **No new mechanism to enforce simplicity that is itself a special case.**

## Done

The four changes in; each touched document simpler and more general; the judgement calls sent to
the reviewing session for the owner; each code commit naming check, test, build, the fingerprint and the
bout-by-bout reading; this plan deleted, its rules in `AGENTS.md` and the recipes.
